Admin

This page is for this server's admins: its accounts, the apps it uses to connect to patient portals and health plans, its list of providers, and what it may contact. Your account isn't an admin, so there's nothing here for you to change.

For an account for someone else, a portal or health plan set up, or anything else about the whole server, ask your admin.

Accounts

An account for each person who signs in. Being an admin lets someone manage accounts; it doesn't show them anyone's records.

More about this

A new account gets a one-time password, and its person chooses their own at first sign-in. Records are shared profile by profile, by each profile's owners, on its Sharing page.

To manage accounts, turn on two-factor sign-in (the authenticator app) or add a passkey for your own account, under Account → Sign-in & security. Admins need one as soon as the server has more than one account.

Backups

A checked copy of the accounts, profiles and records, and of the phone and watch data, written to the backups folder. Copy them off this server too.

The encryption key isn't in the backups. Keep a copy of the key file somewhere else, like a password manager or a USB stick in a drawer: without it no backup can be read, and nobody can recover it.

More about this

A backup holds the database (accounts, profiles, records, settings), each profile's documents and uploads, the setup build, and the watch receiver's data: its database for each profile, as it last saved it, and every upload from a phone it archived. Not in it: your original exports, the encryption key, and the configuration (.env, sources.json). Making one is safe while people use the app and phones upload.

A backup can't be changed afterwards: what was deleted since it was made, like cycle records, is still in it until the backup itself is deleted.

Where the backups folder is on the server is the install's choice (BACKUP_DIR in .env; ./backups by default). Restoring one replaces the live data, so it's done on the server with the app stopped (python -m server.manage restore), never from this page. The watch receiver puts its data back when it's restarted after that.

Check a backup

Restores a backup into a temporary folder beside it, compares it with what it says it holds, then deletes the copy. The live data isn't touched.

More about this

The vendor sends sign-ins straight back here. Nothing is shared with the Sanguity project: the count of connections below stays on this server. Why each install has its own app: docs/connected-sources-oauth.md.

    Provider directory

    The list Find your provider searches, kept on this server: searching it contacts no one.

    More about this

    Sanguity ships with the vendors' test sandboxes and Medicare. Epic's and Oracle Health's published lists can't be shipped under their terms, so each server adds its own copy.

    Lab name matches

    The series each unfamiliar lab name was matched to at an import's preview. These matches apply to every profile on this server, so only admins can change or remove them; a change applies to later imports only.

    More about this

    When an import has a lab test spelled in a way Sanguity doesn't know, the person importing it picks the series it belongs to (or keeps it separate), and that choice is used for later imports from the same source. The matches name tests, never anyone's results or profiles. Results already saved keep their series.
